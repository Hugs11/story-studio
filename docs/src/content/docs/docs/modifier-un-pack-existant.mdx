---
title: Modifier un pack existant
description: Ouvrir un ZIP, un 7z ou un dossier d’histoire existant, puis comprendre ce que Story Studio peut réellement modifier.
---

Si tu possèdes déjà un pack mais pas son projet `.mbah`, Story Studio peut essayer de reconstruire une version modifiable à partir du pack lui-même.

Depuis l’écran d’accueil, choisis **Modifier un pack existant**.

Tu peux sélectionner :

- un fichier `.zip` ;
- un fichier `.7z` ;
- un dossier d’histoire déjà décompressé.

Story Studio analyse d’abord le pack avant de l’ouvrir.

## Quatre résultats possibles

Selon sa structure, un pack peut être :

| Résultat | Ce que tu peux faire |
|---|---|
| **Éditable dans les deux éditeurs** | choisir entre une structure de Dossiers et d’Histoires ou le graphe complet du pack |
| **Éditable uniquement dans l’Éditeur graphe** | travailler directement sur ses Écrans, ses Listes de choix et ses raccords |
| **Lecture seule** | le parcourir dans le Simulateur |
| **Non supporté** | choisir une autre source |

Story Studio ne se contente pas de vérifier que l’archive est valide. Il contrôle aussi comment sa
navigation peut être reprise fidèlement.

Une structure classique peut être reconstruite dans l’Éditeur par menus. Un pack comportant des
parcours complexes, des étapes partagées ou des transitions particulières peut être ouvert dans
l’Éditeur graphe. La lecture seule reste réservée aux packs que Story Studio sait simuler sans
pouvoir encore les modifier de façon fiable.

:::note[Depuis la version 0.9.9]
Grâce à l’Éditeur graphe, Story Studio peut reprendre la quasi-totalité des packs dont il sait lire
la structure. Les résultats **Lecture seule** et **Non supporté** devraient donc rester rares.
:::

## Modifier un pack depuis l’accueil

Le parcours normal est le suivant :

1. clique sur **Modifier un pack existant** ;
2. choisis ou dépose le ZIP, le 7z ou le dossier ;
3. laisse Story Studio examiner sa structure ;
4. s’il convient aux deux éditeurs, choisis **Éditeur par menus** ou **Éditeur graphe** ; si sa
   navigation exige le graphe, Story Studio l’y ouvre directement ;
5. vérifie sa navigation avant d’effectuer des modifications importantes.

Le pack importé commence comme un nouveau travail. Si tu souhaites le conserver, utilise ensuite **Projet → Enregistrer** pour créer un fichier `.mbah`.

:::tip[ZIP ou projet .mbah ?]
Il est tout à fait possible de conserver uniquement le **ZIP**, puis de l’extraire dans Story Studio chaque fois que tu veux le modifier, tant que sa structure reste éditable par Story Studio. C’est simple et cela suffit pour beaucoup de packs.

Pour un projet que tu comptes faire évoluer régulièrement, conserve toutefois aussi le **projet
`.mbah` et ses fichiers sources**.

Un ZIP est une version déjà préparée pour la Lunii : certains médias ont pu être compressés ou transformés lors de sa génération. Enchaîner plusieurs cycles **ZIP → extraction → modification → nouveau ZIP** peut donc entraîner une perte progressive de qualité, notamment sur les audios.

En résumé :

- **ZIP uniquement** : plus simple à conserver et à partager ;
- **`.mbah` + fichiers sources** : préférable pour retravailler et faire évoluer un pack dans le temps.

Le ZIP sauvegarde la **version publiée** ; le `.mbah` sauvegarde le **travail de création**.
:::

## Archive contenant plusieurs packs

Une même archive peut contenir plusieurs packs. Story Studio les examine alors séparément et
affiche l’étape **Cette archive contient plusieurs packs**.

Choisis le pack que tu souhaites ouvrir. Son état indique s’il peut être repris dans l’un des
éditeurs ou seulement simulé. La suite se déroule ensuite comme pour une archive qui ne contient
qu’un seul pack.

Cette sélection ouvre un pack à la fois : elle ne fusionne pas automatiquement le contenu de
l’archive. Pour réunir plusieurs packs dans un nouveau projet, utilise plutôt
[**Agréger des packs**](/story-studio/docs/agreger-des-packs/).

## Pack non éditable mais simulable

Lorsqu’un pack ne peut être repris fidèlement ni dans l’Éditeur par menus ni dans l’Éditeur graphe,
Story Studio peut proposer **Simuler le pack**.

Le Simulateur lit alors la navigation réelle du pack sans prétendre la convertir en structure modifiable.

Cette possibilité est utile pour :

- vérifier le contenu d’un ancien pack ;
- comprendre son parcours ;
- comparer son comportement avec une nouvelle version ;
- retrouver une Histoire ou un média avant de recréer manuellement une partie du pack.

## Un pack que l’éditeur par menus ne sait pas reprendre

L’éditeur par menus n’extrait que les packs qu’il sait reconstruire fidèlement. Pour les autres, Story Studio affiche :

> Ce pack n’est pas compatible avec l’éditeur par menus. Pour le modifier, ouvre-le dans l’éditeur graphe : Projet → Ouvrir un pack.

L’Éditeur graphe sait reconstruire leur navigation sous forme d’Écrans, de Listes de choix et de
raccords, tout en récupérant leurs médias.

## Extraire un pack déjà présent dans l’Arbre

Dans l’Éditeur par menus, un élément **ZIP** peut représenter un pack inclus dans ton projet.

Un clic droit sur cet élément propose notamment :

- **Simuler ce pack…** : parcourir le pack tel qu’il existe ;
- **Extraire l’histoire** : tenter de remplacer le ZIP par des Dossiers et des Histoires modifiables.

Si l’élément ZIP se trouve dans un projet déjà construit, son extraction remplace uniquement cet élément.

Dans un projet vierge, l’extraction peut au contraire devenir la structure principale du nouveau projet.

Le ZIP source reste inchangé.

## Après l’extraction

Avant de modifier fortement un pack extrait :

1. simule quelques parcours importants ;
2. compare les Dossiers, Histoires et retours avec le pack d’origine ;
3. vérifie les médias signalés comme manquants ;
4. enregistre le résultat comme nouveau projet `.mbah` ;
5. passe ensuite par la validation avant de générer un nouveau ZIP.
